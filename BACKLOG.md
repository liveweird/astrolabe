# Product backlog

Updated 2026-11-27 (1.34.0 released). This file tracks **outstanding work only**. Implemented behaviour and release history belong elsewhere:
- [README.md](README.md);
- the [application changelog](web/src/changelog/entries.ts);
- the topic guides under `.claude/docs/`.

Entries are proposals, not delivery commitments.

**Status tags.** Every top-level item under a `##` section opens with one tag:
- `[next]`: what comes next;
- `[todo]`: confirmed, to do;
- `[new]`: proposed, not yet confirmed. That includes the decisions only the user can take. Claude adds items as
  `[new]`, and only the user promotes them;
- `[parked]`: deliberately set aside until a trigger;
- `[blocked]`: waiting on someone or something else.

The `backlog` mod (`liveweird/claude-mods`) summarises the tags on the status line and in `/backlog`.

## Engineering follow-ups

- [new] **`warningWeeks` in `GET /views/team-load` has no web consumer since the Teams page lost its weeks table (1.36).** The document still carries each row's `warningWeeks` and `warningWeeksTruncated` (up to 2,000 weeks, the kernel's budget and its tests); the web reads only the counts. Dropping them is an API change (the spec, `schema.ts`, `TeamLoadKernels`/`TeamLoadView`, the server tests, `planning-model.md`), to be made on its own when the document next changes; until then they are dead weight on the wire.
- [new] **A week-by-team overload view, a heat map (1.36).** The removed "Weeks with a warning" list was team by team, so it could not answer when overloads cluster across teams; a grid of weeks against teams, each cell coloured by its verdict and linking to the team's weekly load, would. It needs a document shaped by week (or `warningWeeks` kept for it, see the item above) and an accessible text path (the heat map's cells are decoration, as the team strip's are).
- [new] **Recompute a CURRENT saved run's `projects` at read time (1.33).** `projects[]` of a saved proposal is as of the save, and milestones of teams outside the run are not part of its state, so the overview's saved bars can show a project span another team has since moved. Recompute it at read for a CURRENT run (`SpanKernels.projectSpanChanges(currentPlan, stored spans + moves, calendar)`) before the overview draws saved bars.
- [new] **Skip a view's work when nothing it reads has changed (1.22 Q1b, Q1c).** 1.22's validator is a hash of the rendered document, so a `304` saves the transfer and not the view's statements and kernels (`timeline.md` "Measured figures": the `304` of the largest team view is only 2-9 ms under the `200`). A pre-check (a data stamp read before the view, or version counters bumped by the writes) would skip the work too; the input table is `planning-model.md` "View validators", and every missed input would be a stale page. Build it only if a measurement shows the work is the cost.
- [new] **Count "from this week on" in the teams table and on Home, and a configured time zone for "this week" (1.22 Q4).** 1.22 hid past weeks only in the Teams page's weeks table (removed 1.36; the team page's weekly table lists every week); the three counts of a team row, `totals` and Home's two team figures still count every week. "This week" is the Monday of the server's UTC week (`currentWeekStart`), so around midnight on a Monday in another zone last week is still "this week" for an hour or two; there is no plan time zone.
- [new] **List the weeks without capacity as ranges on the Teams page (1.22 Q4b).** The weeks without any capacity stay a count per team; "2027-03-01 to 2027-04-11, 6 weeks" per team would need a new member of the document and a place on the Teams page.

- [new] **Home's "N not scheduled yet" opens the whole Teams table (1.32).** A filter for the teams with milestones not scheduled yet would need a new parameter; today each team's "Not scheduled" link is one click away.
